# ADR 0074: LLMクライアントをopencodeからdshへ変更する

## 決定

- 対話・自動実行のLLMクライアントをDeepSeek Harness（dsh）へ変更する。
- リポジトリの指示は`AGENTS.md`、再利用手順は`.agents/skills/`に置き、dshの標準探索に任せる。
- 既定のモデル経路はDeepSeek officialとする。
- opencode固有の設定と依存は削除する。過去のセッション暗号文は履歴として残す。

### 決定の理由

- dshは`AGENTS.md`と`.agents/skills/`を標準で読み、既存資産を移行なしで使えるため。
- DeepSeekが保守するハーネスへ寄せることで、モデル経路と実行基盤の重複を減らせるため。
- ヘッドレス実行と永続セッションを持ち、対話と自動実行を同じ基盤で扱えるため。

## 不採用

- opencodeを継続する
  - クライアント切り替えの要求を満たさず、設定と依存が二重に残るため。
- Codexを主クライアントにする
  - 既定のモデル経路をDeepSeek officialへ揃える要求に合わないため。
- opencodeとdshを併用する
  - 設定・スキル・セッション保存の正本が二つになり、運用コストが増えるため。

## 補足情報

### 背景

- これまでopencodeを主クライアントとして、Codex系の補助経路と併用していた。
- dshが指示ファイルとスキルの標準探索を持ち、ヘッドレス実行も提供するようになった。

### 制約事項

- dshはdeveloper previewであり、互換性の破壊的変更があり得る。
- モデルのAPIキーは利用者側で用意する必要がある。
- opencode専用のプラグインはdshではそのまま動かない。

### 限界と再検討条件

- 限界: dshのdeveloper preview期間中の互換性は保証しない。
- 再検討条件: dshの安定版移行、モデル経路の変更、またはopencode固有機能が必要になった場合。
