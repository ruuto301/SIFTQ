# ADR 0077: D1 を Cloudflare 内で毎日 R2 へ暗号化バックアップする

## 決定

- D1 の日次バックアップは GitHub Actions に依存せず、Worker の Cron Trigger と R2 で完結させる。
- 実行は毎日 1 回（03:00 JST）とし、暗号化した SQL ダンプを R2 の非公開バケットへ保存する。
- 暗号化は AES-256-GCM とし、鍵は既存のセッション署名用シークレットから HKDF-SHA256 で導出する。専用の鍵や鍵ファイルは追加しない。
- 保持期間は 30 日とし、日次実行時に古いアーカイブを削除する。
- 復元は手元で行い、既定はローカル D1 への訓練、本番は明示指定と確認を必須とする。
- セッションのバックアップ（age）とは鍵も保存先も分ける。

### 決定の理由

- GitHub に依存しないことで、リポジトリの肥大と外部サービス障害の影響を避けられる。
- 既存シークレットからの HKDF 導出は、秘密の追加管理をせずに用途分離できる標準的な方法である。
- 30 日保持は個人運用の容量と復旧要件のバランスで決めた。

### 代替案

- GitHub Actions でリポジトリへ保存する案は、GitHub 依存が残り、日次コミットで履歴が肥大するため却下した。
- age による暗号化は、Worker の WebCrypto で標準機能として扱えず WASM 依存が増えるため却下した。
- 専用の暗号化鍵は、管理する秘密が 1 つ増えるため却下した。

### 影響

- Worker に Cron Trigger と R2 バインディングが増える。
- ルート秘密を変更すると新しい鍵になるため、旧シークレットを保持期間中は保管する必要がある。
- 完全な事業者障害対策は対象外とし、D1 の time-travel と合わせて使う。
