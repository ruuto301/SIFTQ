# ADR 0076: dshのセッションをageで暗号化してバックアップする

## 決定

- DeepSeek Harness（dsh）のセッションは、セッション単位のログファイルとしてバックアップする。
- 平文を置かず、zstd圧縮とage（X25519）暗号化を経て公開リポジトリの専用ディレクトリへ保存する。
- 秘密鍵はリポジトリ外に置き、追跡するのはrecipient公開鍵だけにする。
- バックアップと復元は自動化せず、利用者が指定したタイミングで手動実行する。
- opencodeのデータベースバックアップは廃止する。過去の暗号文は履歴として残す。

### 決定の理由

- dshのセッションはセッション単位のファイルとして保存され、Codexと同じファイル単位の扱いができるため。
- データベース全体のスナップショットを必要とせず、差分のあるセッションだけを更新できるため。
- クライアント切り替え後も、公開リポジトリへ平文を置かない方針を維持できるため。

## 不採用

- opencodeのデータベースバックアップを残す
  - 切り替え後は更新されず、保存対象の正本が二つになるため。
- セッション保存ディレクトリ全体を単一アーカイブにする
  - セッション単位の差分更新ができず、再作成の頻度とサイズが増えるため。
- バックアップを自動スケジュールする
  - 無人の増加を招き、履歴量を制御しにくいため。

## 補足情報

### 背景

- 以前はCodexのセッションとopencodeのデータベースを別々の形式でバックアップしていた。
- dshはセッションごとの永続ログを持ち、保存形式がファイル単位で揃う。

### 制約事項

- 追跡する暗号文とメタデータは公開される。内容は復号鍵がない限り読めない。
- 復号鍵を失うと履歴を復元できないため、鍵の別経路バックアップが必須となる。
- 画像などの添付実体はセッションログとは別に保存され、このバックアップの対象外とする。

### 限界と再検討条件

- 限界: 添付実体は対象外であり、セッションログだけでは画像を復元できない。
- 再検討条件: dshの保存形式が変わった場合、または添付実体も保存対象にする場合。
